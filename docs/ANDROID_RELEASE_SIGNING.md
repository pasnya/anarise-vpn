# Подпись Android-релизов

Для всех новых Android-релизов ANARISE используется один постоянный production-ключ. Его сертификат имеет отпечаток SHA-256:

`49:D2:26:AA:32:04:6E:FF:91:6D:3D:F0:7F:82:0E:E9:F9:5A:4A:B0:DA:60:B5:7D:05:A8:B3:E6:BD:B7:E6:FB`

Параметры сертификата: alias `anarise-release`, RSA 4096, PKCS#12, владелец `CN=ANARISE VPN, OU=Release, O=ANARISE, L=Moscow, C=RU`. Закрытый ключ создан для проекта и не должен пересоздаваться для очередного релиза.

## Где хранится

- Основной рабочий ПК: `%USERPROFILE%\.android\anarise-release.jks`; пароль и alias находятся в Windows Credential Manager под записью `ANARISE_ANDROID_RELEASE_SIGNING`.
- Второй ПК: `D:\Codex\anarise\android\signing\anarise-release.jks`; пароль хранится в `release-password.dpapi`, зашифрованном DPAPI для учётной записи Windows `Kek`.
- GitHub Actions хранит секреты `ANARISE_KEYSTORE_BASE64`, `ANARISE_STORE_PASSWORD`, `ANARISE_KEY_ALIAS` и `ANARISE_KEY_PASSWORD`.

Keystore, пароли и DPAPI-файл нельзя добавлять в Git, публиковать в релизах или пересылать открытым текстом. Каталог `android/signing/`, файлы `*.jks` и `*.keystore` исключены из Git. Если потребуется восстановление, используйте защищённую копию keystore и заново задайте те же четыре GitHub Actions secrets; новый сертификат с другим отпечатком не является заменой.

## Проверка перед выпуском

Перед публикацией Android APK нужно подтвердить, что сертификат собранного APK имеет указанный выше SHA-256, а `versionName` совпадает с тегом релиза. Для обновления существующей установки Android также должен оставаться неизменным `applicationId` и повышаться `versionCode`.

## Совместимость со старыми установками

Исторические APK проекта встречались с несколькими разными сертификатами, а прежний production-keystore на доступных компьютерах и в текущих GitHub secrets не найден. Поэтому отпечаток выше закреплён как единый ключ для будущих выпусков. Android не установит APK с этим ключом поверх приложения, уже установленного с другим сертификатом: для таких установок потребуется однократное удаление старой версии и установка новой. После перехода обновления с тем же ключом устанавливаются поверх.
