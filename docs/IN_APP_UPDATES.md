# Обновление приложения из интерфейса

При запуске приложения проверяются последние стабильные GitHub Releases. Черновики и предварительные выпуски не предлагаются. Если для платформы есть подходящий новый файл, приложение скачивает его по HTTPS, проверяет SHA-256 из метаданных GitHub, когда он доступен, и передаёт установку системному механизму платформы.

## Файлы релиза

Имена файлов должны сохранять шаблоны сборочных workflow:

- Windows: `AnariseVPN-Windows-x64-v<версия>.zip` — архив публикуемых файлов приложения.
- macOS Apple Silicon: `AnariseVPN-macOS-arm64-v<версия>.dmg`.
- macOS Intel: `AnariseVPN-macOS-x64-v<версия>.dmg`.
- Android ARM64: `AnariseVPN-Android-arm64-v<версия>.apk`, подписанный постоянным production-ключом.

## Установка по платформам

- Windows распаковывает ZIP после закрытия приложения, сохраняет предыдущую папку до успешной замены и запускает обновлённую версию. Для установки в защищённую папку Windows покажет запрос подтверждения администратора.
- macOS монтирует DMG, заменяет текущий `Anarise.app` и перезапускает приложение. Если оно находится в `/Applications`, macOS может запросить разрешение администратора. Запускать обновление следует из установленной копии приложения, а не из смонтированного DMG.
- Android загружает APK в приватный кэш и открывает системный установщик. При первом обновлении Android может попросить разрешить установку приложений из ANARISE; установку APK пользователь подтверждает в системном диалоге. Android разрешает обновление поверх только при совпадении подписи APK с установленной версией.

Если GitHub не вернул готовый файл нужной платформы или проверка файла завершилась ошибкой, обновление не устанавливается.
